# 存储与固件升级

## Flash 布局

固件使用以下 16 MiB Flash 布局：

| 区域 | 起始偏移 | 容量 | 内容 |
|---|---:|---:|---|
| 固件 | `0x000000` | 2 MiB | 程序 |
| `/rom` | `0x200000` | 1 MiB | RM1 只读资源 |
| `/system` | `0x300000` | 12 MiB | FAT 卷、游戏和素材 |
| LittleFS 根 `/` | `0xf00000` | 1 MiB | LittleFS v2，包含 `/state/` 配置目录 |

`/rom` 使用 RM1 ROMFS，默认存放菜单背景。字体位图仍编入固件；两个背景路径均不可读时菜单显示黑底。

构建提供三种镜像：

- `tufty-nes-flash.uf2`：仅程序，要求设备已有有效文件系统。
- `tufty-nes-with-romfs.uf2`：程序及完整 /rom，保留 /system 与 LittleFS。
- `tufty-nes-with-filesystem.uf2`：程序及三个文件系统，可初始化空白设备；**覆盖已有游戏、资源及配置**。

运行中的固件不会自动格式化存储。完整镜像在主机侧生成有效 FAT 和 LittleFS，再按上述固定偏移刷入。各镜像均带下文所述 SDK 兼容块。

带资源的镜像采用 sparse 打包，省略文件系统未使用的擦除扇区，缩短传输和刷写时间；分区容量及镜像覆盖范围不变。刷入完整文件系统镜像后，原有游戏和配置不再出现在新文件系统中，但空闲扇区里的旧字节不保证被清除。原始 `.bin` 分区镜像仍为完整尺寸。

## 游戏与 USB 磁盘

游戏位于 `/system/roms/`。运行游戏时 FAT 只读；进入 USB 磁盘模式后固件卸载 FAT，由电脑独占读写。只有 `/system` 对外暴露，`/rom` 和 `/state` 不显示在该磁盘中。

菜单首先读取 `/system/roms/games.idx`。这是由 `tools/build_game_index.py` 生成的 GIDX v1 索引，包含固定顺序、标题、简介和 58×80 `.565` 封面标志；索引最大 256 KiB、最多 128 条记录。索引无效、版本不支持或缺失时，固件回退到第一层目录扫描并按文件名排序。索引路径和记录中的文件名均为相对 `roms/` 的单层名称，设备不会在启动时预读或校验全部 ROM，只有用户启动游戏时才读取实际 ROM 并执行格式和大小检查。设备不修改索引；资源变更后请在电脑上重新生成并安全弹出磁盘。

FatFs 支持 512、1024、2048、4096 字节逻辑扇区，底层 Flash 按 4096 字节物理块擦写。磁盘操作完成后应安全弹出，再等待设备自动重启。

## 升级注意事项

普通固件数据限制在前 2 MiB。UF2 同时保留 Pico SDK 默认的 RP2350-E10 兼容块，其行为取决于芯片修订版本：

- **A3 及以后**：Boot ROM 忽略带标签的兼容块。
- **A2**：Boot ROM 可能写入该块，擦除 State 最后一个扇区；升级前应备份配置。

A2/A3 指芯片修订版本，与 RP2350A/B 封装不同。兼容块地址为 `0x10ffff00`，family 为 `0xe48bff57`，行为与 SDK 默认设置一致。构建后的 UF2 检查分别验证普通固件范围和兼容块。
